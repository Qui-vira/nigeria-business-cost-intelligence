# NBS CPI (state) - Cleaning Validation

Generated by `src/cleaning/clean_nbs_cpi.py` on 2026-09-16 12:04.

> **What this dataset is.** The NBS CPI **state** table (`Table-5`) only - Food and All Items, by state, on the 2024 = 100 base. The national, urban, rural and pre-rebasing sheets in the same workbooks are deliberately not processed.

## Environment

- `xlrd` **2.0.2** was installed so the genuine OLE2 `.xls` workbook in `CPI_Report_March_2026.zip` could be read. The project has no dependency manifest, so the version is recorded here rather than in a new one.
- `openpyxl` 3.1.5 reads the other 17 releases.
- `extraction_method` records which reader produced each row.

## Scope and exclusions

- **Releases processed:** 18 (2025-02-01 to 2026-07-01, no gaps)
- **Rows:** 6512 - 3922 INDEX, 2590 change

Nine sheets sit in these workbooks and none is ingested:

| Excluded sheet | Why |
|---|---|
| `Table1`, `Table2`, `Table3`, `Table4` | national / urban / rural series - out of scope for a state dataset |
| `Table1 (2)`, `Table2 (2)`, `Table3 (2)`, `Table3 (3)`, `Table4 (2)` | pre-rebasing working sheets: two bases in identically-headed adjacent columns, ~96,857 `#REF!` cells (all in `Table1 (2)`), and `Table3 (3)` an exact duplicate of `Table3 (2)` |

A check asserts that every non-Table-5 sheet present is on this list, so a newly-added sheet fails the run instead of being ignored.

Two profiling anomalies stay documented but outside this dataset: the **October and November 2025 `Table2`** sheets publish a 1995-base series under a `Base Year 2024 = 100` title (All-Items runs 1.93 to 128.89 over 370 rows), and the `(2)` sheets carry the dual-base history.

## Two documented source defects

### 1. February 2026's year-ago column is labelled 2025-02 but holds 2025-01 data

`CPI_Report_FEBRUARY_2026.zip` sheet `Table-5` row 3 column C reads **2025-02-01**. All 74 values beneath it are byte-identical to the published **January 2025** column and none matches published February 2025. The March 2026 release is the control and matches its own year-ago month 74/74.

**Both the 74 year-ago INDEX cells and the 74 `CHANGE_YOY_PCT` cells are excluded from the canonical output** - the year-on-year rates are computed from that same disputed denominator, so they cannot be represented as true February 2026 year-on-year changes. They are **not** relabelled to January, **not** published as February, and **not** recomputed from another release (D-51).

All 148 excluded cells are retained as evidence with full provenance, flagged `YEAR_AGO_PERIOD_LABEL_DATA_CONFLICT`. A sample:

|---|---|---|---|---|
| `C5` | Abia | FOOD | `INDEX` | 115.21 |
| `I5` | Abia | FOOD | `CHANGE_YOY_PCT` | 10.620261294118365 |
| `D5` | Abia | ALL_ITEMS | `INDEX` | 115.38 |
| `I5` | Abia | FOOD | `CHANGE_YOY_PCT` | 10.620261294118365 |
| `J5` | Abia | ALL_ITEMS | `CHANGE_YOY_PCT` | 14.683629933041843 |

### 2. April 2025 assigns 67 of 74 values to states two later releases contradict

The published values are kept **exactly as NBS published them** - nothing shifted, replaced or relabelled. All 74 April 2025 current-month INDEX rows carry `STATE_VALUE_ALIGNMENT_DISPUTED` and `is_primary_release = FALSE` (D-52).

| Evidence | |
|---|---|
| April current-month rows flagged | 74 |
| Contradicted by both later restatements | 67 |
| The two later restatements agree with each other on | 73 of 74 |
| April's own Monthly/Annual Change columns | internally consistent with its own misaligned block, to 1e-14 |

From Bayelsa (row 11) down, each April row carries the value the later releases assign to the **next** state - `Bayelsa 115.819464` in April is `Benue 115.819464` in both May 2025 and April 2026. Because the percentages were already computed from the misaligned block, the defect predates publication. **This is a source alignment defect, not a revision.**

The two later restatements themselves disagree on exactly one cell: **Borno FOOD, observation 2025-04**, is published as three different values - `114.69492` (2025-04), `146.650854` (2025-05), `136.650854` (2026-04).

## Cross-release comparison

`Table-5` republishes its year-ago and prior-month columns, so the same state-month is published up to three times. **Every pair is compared**, not just each later publication against the first - otherwise a disagreement between two later restatements would be invisible. The comparable population depends on what the canonical output contains, so it is computed, never assumed.

| Classification | Count |
|---|---|
| `BYTE_IDENTICAL` | 1936 |
| `PRECISION_ONLY` | 1 |
| `KNOWN_SOURCE_STRUCTURE_CONFLICT` | 135 |
| **`SUBSTANTIVE_REVISION`** | **0** |
| **Compared** | **2072** |

**Genuine substantive revisions: 0.** Every large disagreement is explained by one of the two documented source defects, and the single `PRECISION_ONLY` difference is:

- 2025-08-01 Adamawa ALL_ITEMS: `124.01128017142601` (2025-08) vs `124.011280171426` (2025-09), relative difference 1.1e-16

Nothing is collapsed onto a latest value: every publication keeps its own row, told apart by `release_month`, so any disagreement stays auditable. The tolerance is 1e-12.

## The comparability warning

Every one of the 6512 rows carries NBS's own restriction verbatim:

> Indices may not be used for inter-state price comparison because market baskets differ state to state.

It is printed inside the source table, in the label column of the row below the last state. **These index levels must not be used to rank states by absolute cost.** A state's values are comparable with that same state's other months, not with another state's.
